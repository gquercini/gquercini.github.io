SQL & Data Quering — Tutorial 2

SQL fundamentals

1 Introduction to SQL

All exercises use one table at a time; no joins are required. The property table contains one row per property and has the following columns:

property(property_id, property_type, built_area, land_area,
num_main_rooms, number_of_units, street_id)

The property_type values include 'Appartement' and 'Maison'. Assume that some land_area and built_area values are NULL.

1.1 Selecting columns and query order

Exercise

Exercise 1.1 Write a query that displays the property identifier, type, built area, and number of main rooms for every property. Then state the order in which the clauses are written in SQL and the logical order in which the database evaluates them. Include WHERE, GROUP BY, HAVING, ORDER BY, and LIMIT in both orders, even though this query does not use them all.

Solution 
SELECT property_id, property_type, built_area, num_main_rooms
FROM property

Written order: SELECT, FROM, WHERE, GROUP BY, HAVING, ORDER BY, LIMIT.

Logical evaluation order: FROM, WHERE, GROUP BY, HAVING, SELECT, ORDER BY, LIMIT.

1.2 Filtering rows with WHERE

Exercise

Exercise 1.2 Write a query that lists the identifiers, built areas, and number of main rooms for apartments whose built area is at least 60 and at most 100 square metres, and that have at least three main rooms. Use comparison operators and AND. Make sure the text value is written as a string literal.

Solution 
SELECT property_id, built_area, num_main_rooms
FROM property
WHERE property_type = 'Appartement'
  AND built_area >= 60
  AND built_area <= 100
  AND num_main_rooms >= 3

Text values are enclosed in single quotes. The comparison predicates filter individual rows.

Exercise

Exercise 1.3 Write two queries:

  • Find houses with a built area greater than 150 square metres, or apartments with at least five main rooms. Use AND, OR, and parentheses to make the intended grouping explicit.
  • Find properties that are not apartments and have at least three main rooms. Use NOT.
Solution 
SELECT property_id, property_type, built_area, num_main_rooms
FROM property
WHERE (property_type = 'Maison' AND built_area > 150)
   OR (property_type = 'Appartement' AND num_main_rooms >= 5)

SELECT property_id, property_type, num_main_rooms
FROM property
WHERE NOT (property_type = 'Appartement')
  AND num_main_rooms >= 3

1.3 Sorting and limiting results

Exercise

Exercise 1.4 Write a query that lists every property, sorted first by type in ascending order, then by built area in descending order, and finally by property identifier in ascending order.

Solution 
SELECT property_id, property_type, built_area
FROM property
ORDER BY property_type ASC, built_area DESC, property_id ASC

Exercise

Exercise 1.5 Write a query to find the ten largest houses by built area. Return the property identifier and built area. If several properties have the same area, sort those by identifier in ascending order.

Solution 
SELECT property_id, built_area
FROM property
WHERE property_type = 'Maison'
ORDER BY built_area DESC, property_id ASC
LIMIT 10

1.4 Aggregates and groups

Exercise

Exercise 1.6 For houses, write one query that returns the number of properties, total built area, average built area, and the smallest and largest built areas. Choose the aggregate function that answers each question, then explain what each result represents.

Solution 
SELECT COUNT(*) AS property_count,
       SUM(built_area) AS total_built_area,
       AVG(built_area) AS average_built_area,
       MIN(built_area) AS smallest_built_area,
       MAX(built_area) AS largest_built_area
FROM property
WHERE property_type = 'Maison'

COUNT counts rows, SUM totals the values, AVG calculates their mean, and MIN and MAX return the smallest and largest values.

Exercise

Exercise 1.7 Write a query that returns the number of properties and average built area for each property type. How many rows does the result contain? Which columns can appear in the SELECT list of a grouped query? Could you add property_id without aggregating it? Explain.

Solution 
SELECT property_type,
       COUNT(*) AS property_count,
       AVG(built_area) AS average_built_area
FROM property
GROUP BY property_type

The result has one row per distinct property type. In a grouped query, each selected expression must either be a grouping column or an aggregate expression. Therefore, property_id cannot be added as-is.

1.5 Filtering groups with HAVING

Exercise

Exercise 1.8 For each property type, count properties with at least three main rooms and calculate their average built area. Return only groups containing at least 100 properties. Explain why the row filter belongs in WHERE and the group filter belongs in HAVING.

Solution 
SELECT property_type,
       COUNT(*) AS property_count,
       AVG(built_area) AS average_built_area
FROM property
WHERE num_main_rooms >= 3
GROUP BY property_type
HAVING COUNT(*) >= 100

WHERE filters individual rows before grouping. HAVING filters the resulting groups and can use aggregates such as COUNT(*).

1.6 Counting and missing values

Exercise

Exercise 1.9 Write a query that returns (1) the total number of properties, (2) the number of properties with a recorded land area, and (3) the number of distinct property types. Explain the difference between COUNT(*), COUNT(column), and COUNT(DISTINCT column).

Solution 
SELECT COUNT(*) AS total_properties,
       COUNT(land_area) AS properties_with_land_area,
       COUNT(DISTINCT property_type) AS distinct_property_types
FROM property

COUNT(*) counts rows. COUNT(land_area) counts rows where land_area is not NULL. COUNT(DISTINCT property_type) counts distinct non-NULL property types.

Exercise

Exercise 1.10 Write a query that returns the average recorded land area and the average land area when missing values are treated as zero. Also return the total number of properties and the number of properties with a recorded land area. Explain how NULL affects COUNT and AVG, and what COALESCE changes.

Solution 
SELECT COUNT(*) AS total_properties,
       COUNT(land_area) AS properties_with_land_area,
       AVG(land_area) AS average_recorded_land_area,
       AVG(COALESCE(land_area, 0)) AS average_with_missing_as_zero
FROM property

COUNT(land_area) and AVG(land_area) ignore NULL values. COALESCE(land_area, 0) replaces each NULL with zero before AVG is calculated, so the second average includes every row and answers a different question.

2 Review with a second table

These recap exercises use only the sales_transaction table. Each row represents one transaction.

sales_transaction(transaction_id, transaction_date, transaction_type, property_id, property_value)

Assume some property_value values are NULL.

Exercise

Exercise 2.1 Write a query that displays the transaction identifier, date, type, and property value for every transaction.

Solution 
SELECT transaction_id, transaction_date, transaction_type, property_value
FROM sales_transaction

Exercise

Exercise 2.2 Write three queries:

  • Find sales with a property value of at least 200,000.
  • Find transactions that are expropriations or have a property value below 50,000.
  • Find transactions that are not sales.

Return the transaction identifier and relevant columns. Use the transaction type values ‘Vente’ and ‘Expropriation’, comparison operators, and correctly quoted text values.

Solution 
SELECT transaction_id, transaction_date, property_value
FROM sales_transaction
WHERE transaction_type = 'Vente'
  AND property_value >= 200000

SELECT transaction_id, transaction_type, property_value
FROM sales_transaction
WHERE transaction_type = 'Expropriation'
   OR property_value < 50000

SELECT transaction_id, transaction_type
FROM sales_transaction
WHERE transaction_type <> 'Vente'

Exercise

Exercise 2.3 Write a query for the ten highest-valued sales. Show the transaction identifier, date, and property value. Sort by property value descending, then transaction date ascending, then transaction identifier ascending.

Solution 
SELECT transaction_id, transaction_date, property_value
FROM sales_transaction
WHERE transaction_type = 'Vente'
ORDER BY property_value DESC, transaction_date ASC, transaction_id ASC
LIMIT 10

Exercise

Exercise 2.4 For sales, write a query returning the number of transactions, total value, average value, minimum value, and maximum value. Then write a query returning the transaction count and average value for each transaction type.

Solution 
SELECT COUNT(*) AS transaction_count,
       SUM(property_value) AS total_value,
       AVG(property_value) AS average_value,
       MIN(property_value) AS minimum_value,
       MAX(property_value) AS maximum_value
FROM sales_transaction
WHERE transaction_type = 'Vente'

SELECT transaction_type,
       COUNT(*) AS transaction_count,
       AVG(property_value) AS average_value
FROM sales_transaction
GROUP BY transaction_type

Exercise

Exercise 2.5 For each transaction type, calculate the number and average value of transactions worth at least 100,000. Return only groups with at least 100 transactions, sort from highest to lowest transaction count, and return the first five groups.

Solution 
SELECT transaction_type,
       COUNT(*) AS transaction_count,
       AVG(property_value) AS average_value
FROM sales_transaction
WHERE property_value >= 100000
GROUP BY transaction_type
HAVING COUNT(*) >= 100
ORDER BY transaction_count DESC
LIMIT 5

Exercise

Exercise 2.6 Write one query that returns the total number of transactions, the number of transactions with a recorded property value, the number of distinct transaction types, the average recorded value, and the average when missing values are treated as zero.

Solution 
SELECT COUNT(*) AS total_transactions,
       COUNT(property_value) AS transactions_with_value,
       COUNT(DISTINCT transaction_type) AS distinct_transaction_types,
       AVG(property_value) AS average_recorded_value,
       AVG(COALESCE(property_value, 0)) AS average_with_missing_as_zero
FROM sales_transaction
