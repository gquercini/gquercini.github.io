Neo4j : querying graph data

Setting up the work environment.

  • Download Neo4j Desktop and install it on your computer.

  • On the left menu, select Instances and then Get started to create your first instance.

  • Specify an instance name (for instance, Graph analytics), select the latest version and enter a new password.

  • Click on Create and wait.

  • When the instance is ready, click on Connect and then select Query. This will open an interface to write queries against your graph.

The database

The database consists of data obtained from MovieLens, a recommendation system whose users rate movies on a scale from 1 to 5, depending on how much they like them.

MovieLens uses these ratings to recommend movies that its users are likely to enjoy. The dataset is modeled as a directed graph and contains 100,004 ratings for 9,125 movies, given by 671 users between January 9, 1995 and October 16, 2016. The dataset also contains the names of each movie’s directors and actors.

Chaining queries with WITH

Cypher allows you to specify complex queries composed of multiple queries chained together with the WITH clause. We will now look at an example that returns the titles of movies rated by at least 100 users.

A first attempt might look like this:

MATCH (n:Movie)<-[:RATED]-(u:User) WHERE count(u) >= 100
RETURN n.title_en
LIMIT 5;

However, this query produces an error:

Invalid use of aggregating function count(...) in this context (line 1, column 42 (offset: 41))
"MATCH (n:Movie)<-[:RATED]-(u:User) WHERE count(u) >= 100"

As in SQL, we cannot use aggregate functions in the WHERE clause.

A correct formulation requires the WITH clause to chain two queries. The first counts the number of ratings for each movie:

MATCH (n:Movie)<-[:RATED]-(u:User) 
RETURN n, count(u) as nb_rates

The second takes the first query’s results as input and filters out movies for which nb_rates < 100. To chain the two queries, we replace the first query’s RETURN clause with a WITH clause, as follows:

MATCH (n:Movie)<-[:RATED]-(u:User) 
WITH n, count(u) as nb_rates
WHERE nb_rates >= 100
RETURN n.title_en

Movie recommendation system

We will now see how Neo4j can be used effectively in a real application by implementing queries that form the basis of a simple movie recommendation system. This system is based on the idea of collaborative filtering.

This approach recommends movies to a user \(u\) that they have not rated yet and that other users with similar preferences have loved. In this context, we say a user loves a movie if they rated it at least 3.

The diagram below illustrates the principle of collaborative filtering.

User \(u\) loves 6 movies, 3 of which are also loved by user \(v\) (the black nodes); it is reasonable to think that \(u\) might also love the two movies that \(v\) loves and that \(u\) has not rated yet.

Collaborative filtering relies on calculating a similarity score between two users. Several similarity scores are possible in this context; here, we will use the Jaccard coefficient. Let \(L(u)\) and \(L(v)\) be the sets of movies loved by \(u\) and \(v\), respectively; the similarity score \(J(u,v)\) between \(u\) and \(v\) is defined as:

\[ J(u, v) = \frac{|L(u) \cap L(v)|}{|L(u) \cup L(v)|} \]

To recommend movies to a target user \(v\), the recommendation system calculates the similarity score between \(v\) and all other users in the system, then suggests movies to \(v\) that they have not rated yet and that the \(k\) most similar users have loved.

We will now write a Cypher query to recommend movies to the target user \(v\), whose ID is 3.
